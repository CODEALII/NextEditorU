# Testing and verification

## Automated offline checks

Run from the repository root:

```powershell
python -m unittest discover -s tests -v
python -m compileall -q worldstudio tests tools
```

The suite uses synthetic fixtures and, when present, the user-supplied files under `NSMBU Modding Project/`. Local game files are read in memory and are not included in exports or commits.

Check a directed route from a declared start to one or more required points:

```powershell
python -m worldstudio validate-graph --entry W101 --require W102 --require W103
```

Repeat `--entry` to allow multiple starts and `--require` for each required destination. To validate an edited saved project, pass its `.nws.json` file before these flags. Reachability follows the point table's normal and secret destination lists. The editor and export also use the same route checks: a newly added same-world destination must have a directed segment chain, and route edits must preserve chains that existed in the baseline. Cross-world edges and pre-existing disconnected chains are not used as local route failures. The check requires locally resolvable point and route rows; unresolved local route endpoints leave it conservative. This does not simulate unlock state, route movement, level loading or save persistence.

The WebGL page is generated locally from parsed scene data. For the supplied W1 BFRES it decodes 17 shared BC1/BC3 albedo textures across all 36 shapes with UVs, applies a 50% alpha cutout, and packs geometry into little-endian typed buffers. It also exposes six shared BC5 SNORM `_n0` maps across 22 shapes as R/G diagnostic colors; this view does not reconstruct normals or affect lighting. In the supplied W1 file, a separate sampler-checked `_o0` view decodes two BC5 UNorm maps (`Mask` and `MaskOpaque`) across 11 UV meshes; it displays stored channels without assigning shader meaning. Local raw and detiled hashes are regression-tested, and headless Chrome/SwiftShader loaded 42 shapes, enabled the mode, and showed the selected `Mask` reference without a WebGL error overlay. Ignored screenshot evidence is `local/evidence/preview-w1-bc5-unorm-diagnostic.png`. The separate `_o1` diagnostic decodes one BC4 UNorm map (`RouteW1_msk`) across seven UV meshes as grayscale; local raw and detiled fingerprints are checked, and headless Chrome/SwiftShader loaded 42 shapes, enabled the mode, and inspected the selected route shape without a WebGL error overlay. Evidence is `local/evidence/preview-w1-bc4-o1-diagnostic.png`. Neither sampler view claims material semantics. Wireframe mode deduplicates triangle edges and draws them as lines. The sampled vertex-normal toggle draws direction vectors for at most roughly 5,000 vertices. Shape-name buttons select a row and fill a text-only inspector with material, geometry counts, UV availability, and texture references; Node-backed tests cover selection changes and focus-button wiring. Supported albedo and BC5 maps get cached, nearest-sampled thumbnails capped at 96 pixels; a Node test covers bounded downsampling and a headless Chrome render shows `RouteW1_alb` beside the `RouteW1_nml` diagnostic thumbnail. Per-mesh bounds are computed from the supported position buffer, and camera-focus tests check centering and distance. Viewport clicks run a depth-tested color-ID pass, including the supported base-texture alpha cutout; Node tests cover ID decoding and high-DPI pixel mapping. A headless Chrome/SwiftShader click on the local main-grass surface selected `polySurface1489__mtGrass` and displayed its inspector; evidence is in ignored `local/evidence/preview-w1-pick-rAF.png`. Azimuth, elevation and intensity sliders control the illustrative preview light; a Node-backed test dispatches an input event and checks the shader direction, intensity and value labels. These settings have no effect on game data and do not reproduce NSMBU material lighting. Perspective depth planes follow the scene radius and zoom distance; Node-backed tests cover fit, zoom-out, close-up, edge deduplication, normal-vector generation and generated JavaScript syntax. Local W1 tests check `Grass_alb`, `RouteW1_alb` and `RouteW1_nml` raw/detiled hashes. User-browser GPU behavior remains unchecked. Other BC4 material slots, sampler semantics, shader parameters, UV transforms, light maps, game shaders and animation are not evaluated. The `_o0` and `_o1` channel displays are diagnostics only. The BC5 UNorm `_o0` display remains a channel diagnostic, not a material implementation.
The camera offers Front, Side and Top orientation buttons around the current focus point; orbiting clears the active preset indicator, and Fit view returns to the whole-scene default. An expandable preview-target control accepts model-space X/Y/Z values within ±1,000,000, keeps the target synchronized when focusing a mesh or fitting the scene, and rejects invalid values. Node-backed tests verify preset angles, target validation and generated viewer JavaScript. These view controls only change the preview camera and do not edit game camera data.

The native editor has bounded undo/redo (`Ctrl+Z`, `Ctrl+Y`, or the toolbar). It covers point and route rows, BFRES local-position drafts, camera offset vectors, and terrain imports. Loading or reloading a project clears the history. Undo marks the project dirty; save and export still run their normal validation.

OBJ import streams UTF-8 text and rejects files over 64 MiB, lines over 64 KiB, more than one million lines, more than 500,000 vertex/UV/normal records or attribute-split vertices, more than 200,000 faces, and more than 500,000 total face corners. Each face is limited to the ear-clipper's 1,024-corner ceiling; non-finite or out-of-range positions and UVs fail early. Tests exercise each guard and parse the checked-in island OBJ (29 vertices, 54 triangles). Status text reports vertex and polygon counts while keeping preview import separate from the experimental native replacement.

Before preview or replacement, the OBJ transform dialog supports per-axis scale, XYZ rotation in degrees, and translation in model units. Its Z-up to Y-up preset rotates -90 degrees around X. The transform helper preserves UVs, applies inverse-transpose normal scaling, reverses polygon winding for mirrored transforms, and rejects degenerate scales or out-of-range results. Synthetic checks cover axis conversion, non-uniform normal scaling, mirrored winding, and invalid scale.

The WebGL preview also has an optional BC5 lighting toggle. It builds tangent frames from supported triangles and UVs and reconstructs the positive normal Z component for the preview shader. Node fixtures verify the tangent basis for regular and mirrored UVs and reject degenerate UV triangles; headless Chrome/SwiftShader loaded all 22 locally mapped shapes with tangent buffers and enabled the toggle without shader or page errors. This is an approximation: BC5 channel orientation and game material settings have not been verified.

In the native graph, drag a point to move it on the camera-facing plane and drag empty space to orbit; the wheel still zooms. Supported points convert the dragged model-space position back into local bone XYZ through the known rest-pose parent rotation. Points whose hierarchy is unsupported move only in the labeled preview layout. One completed drag creates one undo step. Transform tests verify rotated-parent world/local conversion, unsupported branches, and camera-plane mapping; the Tk smoke test exercises drag, undo, and redo. These checks do not validate route traversal in game.

## Cemu integration checks

Follow [INTEGRATION.md](INTEGRATION.md) to prepare an isolated profile and preserve the original game tree and saves. Use the normal game resources as a baseline before enabling a generated graphic pack. Record the active pack, input profile, starting node, exact direction tested, destination shown, level result and save/reload result.

Do not treat a successful boot or rendered map as a traversal pass. Keep every export manifest's `game_tested` field false until route, level, progression, persistence and camera checks have actually been observed.
