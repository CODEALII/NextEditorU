# Testing and verification

## Automated offline checks

Run from the repository root:

```powershell
python -m unittest discover -s tests -v
python -m compileall -q worldstudio tests tools
```

Inspect a shader program's declared metadata from the local dump:

```powershell
python -m worldstudio inspect-shaders "NSMBU Modding Project/content/Common/shader/shaderfb.szs" --entry nw4f_cs_shader.sharcfb --program nw4f_cs_route_shader
python -m worldstudio inspect-shaders "NSMBU Modding Project/content/Common/shader/shaderfb.szs" --entry nw4f_cs_shader.sharcfb --program nw4f_cs_route_shader --json
```

The default output is a compact program/interface summary. `--json` prints the complete parsed metadata. Neither mode decodes GX2 instructions or proves the selected runtime variation. The viewer's expandable shader panel shows the material-option candidate and checked BFRES vertex-input bindings, including the original stored format and byte offset; these fields do not assign sampler UV behavior or decode unsupported vertex formats.

The suite uses synthetic fixtures and, when present, the user-supplied files under `NSMBU Modding Project/`. Local game files are read in memory and are not included in exports or commits.

Each export manifest keeps the backward-compatible `changed_entries` list and adds an `entry_changes` record for every changed archive member, including source/output SHA-256 hashes, byte sizes and size delta. The archive-level hashes and `game_tested: false` remain explicit. The local export regression recomputes these values from the source and reopened output archive.

After exporting a saved project, run `python -m worldstudio verify-export <project.json> <export.szs>`. The verifier checks the output hash and path in the manifest, reimports the archive, compares its complete member list and contents with a fresh export from the project, and checks manifest fields and camera companion outputs. A success means the local package roundtrips consistently; it does not test Cemu or game behavior.

Saving changed native or OBJ-preview project content uses atomic per-file replacement to rotate the two most recent previous versions into adjacent `name.backup.json` and `name.backup-2.json` files. Both remain regular loadable projects, so they appear in the existing `*.json` picker; unchanged saves leave both backups untouched, and the status bar reports the newest backup path. The main project and each backup are replaced atomically as individual files; a multi-file rotation is not transactional if a later file operation fails. `test_overwriting_project_creates_openable_previous_version_backup` exercises native project reloads and rotation against the local source resource; the editor smoke test verifies the OBJ-preview save and status.

The Recent menu stores up to ten native-source/project paths and ten preview paths in a versioned JSON file under the user's local application settings. The lists are type-filtered, deduplicated by resolved path, and updated only after a successful open or save. `tests.test_recent_projects` covers ordering, deduplication, filtering, truncation, and malformed settings recovery; the editor smoke test checks native filtering and that canceling the unsaved-changes guard prevents a recent project from opening.

Edits to a native world opened from either an SZS source or saved JSON project are debounced into a checksummed per-user recovery snapshot (maximum 64 MiB), bound to the exact source-file path and hash. Saved lightweight-preview projects use the same flow. Reopening the source offers an explicit restore prompt; declining recovery, discarding unsaved edits, or successfully saving clears the snapshot. Recovery data stays outside the game archive. `tests.test_session_recovery` verifies project/kind/baseline binding, checksums, bounded size, and removal; Tk smoke tests exercise preview, native JSON, and direct-SZS restore plus discard behavior.

Check a directed route from a declared start to one or more required points:

```powershell
python -m worldstudio validate-graph --entry W101 --require W102 --require W103
```

Repeat `--entry` to allow multiple starts and `--require` for each required destination. To validate an edited saved project, pass its `.nws.json` file before these flags. Reachability follows the point table's normal and secret destination lists. The editor and export also use the same route checks: a newly added same-world destination must have a directed segment chain, and route edits must preserve chains that existed in the baseline. Cross-world edges and pre-existing disconnected chains are not used as local route failures. Changed route segments must resolve endpoints in the current world; remote-world endpoints are left unresolved because their archive is outside the project. The check does not simulate unlock state, route movement, level loading or save persistence.

The material inspector shows supported `texmtxN` Texture SRT parameters and matching uniform names declared by the exact assigned shader program. The strict reader checks each parameter dictionary entry, type 31, 28-byte data range, finite values and a zero matrix pointer. Synthetic parser tests and local-W1 checks validate 36 identity `texmtx1` entries plus 11 `texmtx0` entries with negative V translations. The preview does not apply them because the active shader variation, sampler association, transform convention and GX2 operations are not verified. Repeated texture lookups reuse a one-entry read-only BFRES index keyed by exact model bytes; repeated shader loads reuse the one-entry container parse keyed by its exact bytes. Regressions verify changed source bytes invalidate each cache and that callers receive fresh maps.
The camera offers Front, Side and Top orientation buttons around the current focus point; orbiting clears the active preset indicator, and Fit view returns to the whole-scene default. An expandable preview-target control accepts model-space X/Y/Z values within ±1,000,000, keeps the target synchronized when focusing a mesh or fitting the scene, and rejects invalid values. Node-backed tests verify preset angles, target validation and generated viewer JavaScript. These view controls only change the preview camera and do not edit game camera data. Selected-mesh texture cards show decoded-map dimensions and storage formats carried from the supported GX2 references; sampler maps remain diagnostics, not reconstructed game materials. The screen capture is ignored at `local/evidence/preview-w1-material-camera-controls.png`; this does not verify the user's browser GPU.

The selected-mesh inspector draws raw UV triangle charts over the 0–1 tile and reports stored bounds, out-of-range vertex counts, and valid/invalid triangle counts. Its selector covers every supported named UV attribute found on that mesh; the supplied W1 model has `_u0` on all 42 shapes, `_u1` on 42, and `_u2` on 13. It samples dense meshes for display and clips the plotted range at ±1,024 UV units while reporting actual bounds. Charts use stored coordinates only; they do not apply `texmtx` SRT or infer sampler use from shader-input names. Synthetic decoding, little-endian packing, selector switching and drawing tests exercise this path.

Headless Chrome/SwiftShader previously loaded the real 42-shape local W1 page and displayed the selected shape's default `_u0` chart without a WebGL error overlay. The ignored local screenshot is `local/evidence/preview-w1-uv-chart.png`; the per-attribute selector is covered by the generated-JavaScript test harness. This checks offline preview rendering, not Cemu or material behavior in the game.

`extract_rigid_model` decodes observed `_u0` vertex formats `0x80D` float32x2, `0x7` UNorm16x2, `0x207` SNorm16x2, and `0x4` UNorm8x2. Synthetic tests cover each normalization path, signed lower endpoints, and stride bounds. The local W1 dump inventory verifies **36 + 3 + 2 + 1 = 42** decoded UV-bearing shapes; texture attachment tests now include the six formerly omitted shapes.

The native editor has bounded undo/redo (`Ctrl+Z`, `Ctrl+Y`, or the toolbar). It covers point and route rows, BFRES local-position drafts, camera offset vectors, and terrain imports. Loading or reloading a project clears the history. Undo marks the project dirty; save and export still run their normal validation. Native 3D scene extraction and HTML generation run in a background worker; stage messages are sent through the UI event loop while geometry, textures, shader metadata and the viewer page are processed. `test_3d_preview_build_runs_off_tk_thread_and_keeps_events_live` checks that Tk continues processing callbacks while the worker is held, that a progress message reaches the status bar, and that the detached graph snapshot reaches the worker.

OBJ import streams UTF-8 text and rejects files over 64 MiB, lines over 64 KiB, more than one million lines, more than 500,000 vertex/UV/normal records or attribute-split vertices, more than 200,000 faces, and more than 500,000 total face corners. Each face is limited to the ear-clipper's 1,024-corner ceiling; non-finite or out-of-range positions and UVs fail early. Baked-light UV transfer uses an exact nearest-XZ spatial tree; synthetic tests compare far-offset results with brute force and bound source-vertex distance checks. The import compatibility report surfaces ignored material libraries/assignments, vertex colors, smoothing groups, object/group boundaries and non-polygon geometry in the editor and CLI demo notes. Tests also exercise parser guards and parse the checked-in island OBJ (29 vertices, 54 triangles). Status text reports vertex and polygon counts while keeping preview import separate from the experimental native replacement.

When the local W1 dump is available, `test_terrain_project_roundtrip_export_and_reopen` exercises the complete offline path: import the checked-in island OBJ, save and reload the project geometry, export a new SZS, reopen it, extract the replaced grass shape, compare its vertex/index payload, verify every unrelated archive entry, and confirm the source dump is unchanged. Malformed project geometry is rejected by validation before creating an output. Saved table cells must be text; edited bone positions must target unique supported path-model bones and contain three finite coordinates within the BFRES export bound. Invalid rows and positions produce validation errors and block export before any archive is created. The tests record `game_tested: false`; they do not establish collision, route movement, or in-game terrain appearance.

Before preview or replacement, the OBJ transform dialog supports per-axis scale, XYZ rotation in degrees, and translation in model units. Its Z-up to Y-up preset rotates -90 degrees around X. The transform helper preserves UVs, applies inverse-transpose normal scaling, reverses polygon winding for mirrored transforms, and rejects degenerate scales or out-of-range results. Synthetic checks cover axis conversion, non-uniform normal scaling, mirrored winding, and invalid scale.

The WebGL preview also has an optional BC5 lighting toggle. It builds tangent frames from supported triangles and UVs and reconstructs the positive normal Z component for the preview shader. Node fixtures verify the tangent basis for regular and mirrored UVs and reject degenerate UV triangles; headless Chrome/SwiftShader loaded all 26 locally mapped shapes with tangent buffers and enabled the toggle without shader or page errors. This is an approximation: BC5 channel orientation and game material settings have not been verified.

In the native graph, drag a point to move it on the camera-facing plane and drag empty space to orbit; the wheel still zooms. Supported points convert the dragged model-space position back into local bone XYZ through the known rest-pose parent rotation. Points whose hierarchy is unsupported move only in the labeled preview layout. One completed drag creates one undo step. Transform tests verify rotated-parent world/local conversion, unsupported branches, and camera-plane mapping; the Tk smoke test exercises drag, undo, and redo. These checks do not validate route traversal in game.

## Cemu integration checks

Follow [INTEGRATION.md](INTEGRATION.md) to prepare an isolated profile and preserve the original game tree and saves. Use the normal game resources as a baseline before enabling a generated graphic pack. Record the active pack, input profile, starting node, exact direction tested, destination shown, level result and save/reload result.

Do not treat a successful boot or rendered map as a traversal pass. Keep every export manifest's `game_tested` field false until route, level, progression, persistence and camera checks have actually been observed.
